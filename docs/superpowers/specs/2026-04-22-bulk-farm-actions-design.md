# 一键播种与一键收取设计

- 日期：2026-04-22
- 范围：`src/App.tsx`、`src/components/Plot.tsx`、`src/hooks/useGameActions.ts`
- 目标：为农场增加“一键播种”和“一键收取”，在保持当前 React + Tailwind + Motion 架构与现有单块交互不回归的前提下，提供带明显节奏感和空间感的批量操作体验。

## 1. 背景与问题

当前项目已经具备单块播种、单块收取、拖拽收割、HUD 资源反馈和多种主题特效，但随着地块数量提升，纯手动点击会快速转化为重复劳动。直接把批量操作做成“点一下就整片瞬间刷新”虽然成本低，但会破坏当前项目已经建立起来的 Juicy Feedback 方向。

本次设计的核心不是“批量算数”，而是“批量编排”：

1. 一键收取需要有“成熟作物被连续卷走并飞向 HUD”的节奏感。
2. 一键播种需要有“从底部种子栏连续投射到空地”的铺田感。
3. 业务状态与视觉时序必须一致，不能先变数据再硬补动画，也不能让动画层反向驱动核心状态。

## 2. 用户确认的关键约束

经确认，本次功能边界如下：

1. 一键播种默认使用当前 `SeedSelector` 中已选中的种子。
2. 架构路线采用“编排层优先”，先建立批量操作时间线和接口，再接具体抛物线特效。
3. 保持最小必要改动，不引入 Zustand，不整体迁移状态管理。
4. 维持现有右上角功能栏的职责，不把一键按钮塞进抽奖/仓库区域。

## 3. 目标体验

### 3.1 一键收取：流星归巢

点击后，所有成熟作物按极短间隔依次触发：

1. 地块本地先出现“上拔 + 回弹”的收取起手。
2. 作物或金币载体从地块位置起飞，沿短抛物线飞向右上角金币袋。
3. 所有地块不是同时清空，而是跟随序列逐个进入“已处理”表现态。
4. 最终在最后几颗飞行体接近 HUD 时统一完成资源结算，形成“先收，再到账”的连贯体验。

### 3.2 一键播种：天女散花

点击后，使用当前已选种子对可播种空地执行批量播种：

1. 扣费与播种状态立即提交，保证玩家立刻看到整片空地被播下。
2. 种子飞行体从底部种子栏区域出发，按极短间隔飞向每块目标地。
3. 每块地在命中时触发土壤轻压、亮边和短促粒子闪点。
4. 整体节奏强调“快速铺满”，不追求收取那种延后结算的回收感。

## 4. 方案选择与取舍

本次最终采用“业务纯函数 + App 编排层 + Plot 表现层”的三层结构。

### 4.1 不采用纯逻辑优先方案

只在 `useGameActions.ts` 中补 `harvestAll` / `plantAll` 然后直接刷新数据，虽然能最短时间交付功能，但后续补动画时需要重新拆时序，容易出现以下问题：

1. 地块已经变空，飞行动画才开始。
2. 金币已经增加，飞向 HUD 的动画还在路上。
3. 播种和收取两条批量链路各自长出独立的 `setTimeout`，后期难维护。

### 4.2 不采用动画优先方案

如果先做抛物线动画，再让动画反向驱动地块和金币结算，会让业务与表现相互耦合，测试与复用都会变差。

### 4.3 采用编排层优先方案

推荐方案是：

1. `useGameActions.ts` 只负责选择目标、计算可执行数量和生成结算结果。
2. `App.tsx` 负责 bulk action orchestration，统一管理时间线、按钮锁定、坐标测量和动画任务。
3. `Plot.tsx` 只响应自己当前所处的批量表现阶段，不承担全局决策。

这样既能保持业务逻辑可测试，也能把后续音效、特效、HUD 吸附全部挂在同一条时间线上。

## 5. 架构设计

### 5.1 `useGameActions.ts`：纯业务层

该层继续负责纯计算，不引入动画副作用，不直接调 DOM，不在此处写定时器。

建议新增能力如下：

1. 选择器：
   - `getReadyPlotIds(state, now?)`
   - `getEmptyPlotIds(state)`
2. 批量规划：
   - `planHarvestAll(state, now?)`
   - `planPlantAll(state, selectedSeed, now?)`
3. 批量提交：
   - `commitHarvestAll(state, plotIds, now?)`
   - `commitPlantAll(state, plotIds, selectedSeed, now?)`

返回值不只包含 `nextState`，还要包含 UI 编排所需元数据，例如：

1. `plotIds`
2. `totalGold`
3. `totalXp`
4. `affordableCount`
5. `blockedReason`
6. 每块地对应的单块收益或种子信息

这样 UI 层可以直接消费计划结果，不需要重复计算。

### 5.2 `App.tsx`：批量编排层

`App.tsx` 是本次设计的核心落点。这里不替换现有单块交互，只新增“一键操作控制器”。

建议新增本地状态：

1. `activeBulkAction: 'plant' | 'harvest' | null`
2. `isBulkBusy: boolean`
3. `bulkSequence: number[]`
4. `bulkAnimatedPlotIds: number[]`
5. `bulkActivePlotId: number | null`
6. `bulkHarvestFlights: HarvestFlight[]`
7. `bulkPlantFlights: PlantFlight[]`
8. `bulkAnchors`：缓存种子栏起点和金币袋终点坐标

建议新增入口方法：

1. `handleHarvestAllClick()`
2. `handlePlantAllClick()`

这两个入口只做三件事：

1. 调业务层拿批量计划。
2. 生成按 `stagger` 编排的动画任务。
3. 在预设时间点提交资源或地块状态。

### 5.3 `Plot.tsx`：单块表现层

`Plot.tsx` 不感知“一键逻辑”，仅接收表现态 props：

1. `isBulkLocked?: boolean`
2. `bulkPhase?: 'idle' | 'plant-target' | 'plant-impact' | 'harvest-lift' | 'harvest-cleared'`
3. `sequenceIndex?: number`
4. `isBulkHighlighted?: boolean`

对应表现：

1. 播种目标块：亮边、预热感、轻微聚焦。
2. 播种命中：土壤压缩、短闪、粒子点。
3. 收取起飞：作物上拔、地块回弹。
4. 收取完成：回到空地态。

## 6. 数据流与时序

### 6.1 一键收取时间线

一键收取采用“先表现，后结算”的时间线。

流程如下：

1. `App.tsx` 调 `planHarvestAll`，获得可收取地块列表和预估总收益。
2. 根据地块顺序生成批量任务序列：`plotId`、`sequenceIndex`、`launchAt`、`rewardGold`、`cropId`。
3. 依次触发每块地的 `harvest-lift` 表现态，并创建飞向金币袋的 `HarvestFlight`。
4. 当最后一批飞行体接近终点时，统一调用 `commitHarvestAll` 提交：
   - 对应地块清空
   - 增加金币
   - 增加经验
5. 清理批量状态，解除按钮和单块操作锁。

原因：

1. 收取的爽点来自“作物被卷走并回收进 HUD”。
2. 统一结算能避免每块地单独改状态导致的视觉噪音和多次 HUD 波动。

### 6.2 一键播种时间线

一键播种采用“先结算，后表现”的时间线。

流程如下：

1. `App.tsx` 调 `planPlantAll`，得到空地列表、可负担数量和实际播种列表。
2. 若可播种数量为 0，则不给 `alert`，而是使用按钮轻震或 HUD 金币高亮提示失败。
3. 点击后立即调用 `commitPlantAll`：
   - 扣除总金币
   - 将目标地块标记为已播种
4. 之后生成 `PlantFlight[]`，从底部种子栏向目标地块按 `stagger` 连续投射。
5. 每个命中地块在飞行体落点时进入 `plant-impact` 阶段，触发土壤压缩与闪点。
6. 批量播种动画结束后清理状态。

原因：

1. 播种的核心体验是“迅速铺满整片土地”。
2. 若播种也延后状态提交，会让玩家看到种子飞过去却迟迟不落地，节奏偏拖。

### 6.3 地块顺序

建议批量顺序采用“从下到上、从左到右”：

1. 一键播种时更像沿田垄铺开。
2. 一键收取时更像成排卷走。
3. 视觉上比纯数组顺序更自然。

## 7. 动画设计

### 7.1 按钮位置与形态

一键播种与一键收取的按钮放在底部 `SeedSelector` 上方，做成一组悬浮胶囊：

1. 左侧：一键收取
2. 右侧：一键播种
3. 视觉方向：半透明磨砂、轻辉光、与当前神泉/赛博主题兼容

不放进右上角功能栏的原因：

1. 它们属于田地核心操作，而不是系统入口。
2. 与种子选择区域相邻，更符合玩家的操作路径。
3. 底部区域天然适合作为播种飞行动画的起点。

### 7.2 按钮禁用规则

`一键收取` 禁用条件：

1. 当前没有成熟作物。
2. 当前正在执行任何 bulk 动作。

`一键播种` 禁用条件：

1. 当前没有空地。
2. 当前金币不足以购买 1 颗当前种子。
3. 当前正在执行任何 bulk 动作。

引导规则：

1. 有可收取作物时，一键收取按钮有轻微脉冲描边。
2. 全是空地且金币足够时，一键播种按钮有更明显的呼吸辉光。
3. 金币不足时，不使用阻断式 `alert`，而用按钮轻震 + HUD 金币区域闪动提示。

### 7.3 第一版动画分层

第一版不引入 Canvas 粒子系统，只用 React + Motion 搭建主干爽感。

分三层：

1. 地块层：
   - `Plot.tsx` 负责本地命中、上拔、回弹、闪点
2. 飞行层：
   - `App.tsx` 渲染 `PlantFlight[]` 与 `HarvestFlight[]`
   - 使用绝对定位元素和 Motion 位移完成抛物线近似
3. HUD 吸附层：
   - 飞向 `gold-bag-ui`
   - 命中时触发 HUD 轻微缩放或闪光

### 7.4 第一版节奏参数

建议初始参数如下：

一键收取：

1. `stagger = 0.05s`
2. 单颗飞行时长 `0.55s`
3. 最终结算时机：最后一颗起飞后约 `0.45s`

一键播种：

1. `stagger = 0.06s`
2. 单颗飞行时长 `0.50s`
3. 地块命中反馈时长 `0.18s`
4. 状态在点击后立即提交

这些值先固定，后续再根据实际手感微调，不在第一版中引入自适应参数系统。

## 8. 类型设计

建议在 `App.tsx` 或临近文件定义轻量类型：

```ts
interface HarvestFlight {
  id: string;
  plotId: number;
  sequenceIndex: number;
  rewardGold: number;
  startX: number;
  startY: number;
  endX: number;
  endY: number;
}

interface PlantFlight {
  id: string;
  plotId: number;
  sequenceIndex: number;
  seedId: CropType;
  startX: number;
  startY: number;
  endX: number;
  endY: number;
}
```

这样后续渲染飞行体时不需要临时查数据拼接结构，也方便测试序列生成逻辑。

## 9. 错误处理与兼容性

需要重点规避以下风险：

1. 批量操作期间必须锁住单块点击与拖拽收割，否则状态会交叉写入。
2. 飞行动画坐标依赖 DOM 测量，需要在点击时读取最新坐标，而不是长期缓存旧值。
3. 窗口尺寸变化时，按钮和 HUD 的锚点位置可能失效，必要时应在下一次操作前重新测量。
4. 不能把时间控制散落在多个 `map + setTimeout` 中，必须通过统一的 bulk controller 管理。
5. 批量播种使用当前种子，若后续允许道具种子或限时种子，需要保持 `planPlantAll` 的输入来源可替换。

## 10. 测试与验证策略

本次工作以批量业务逻辑和编排状态为主，建议采用以下验证顺序：

1. 先为 `useGameActions.ts` 的批量规划与提交逻辑补充测试：
   - 无成熟地块时一键收取返回阻断原因
   - 金币不足时一键播种返回阻断原因
   - 可播种数量按金币与空地取最小值
   - 一键收取正确累计金币与经验
2. 为 `src/text-sanity.test.ts` 补充批量按钮、批量状态字段和关键 class/文本回归断言。
3. 运行 `npm test`
4. 运行 `npm run lint`
5. 手工预览验证：
   - 批量期间按钮和单块交互已锁定
   - 一键收取为连续归巢，而不是同步消失
   - 一键播种为连续铺田，而不是瞬间刷新
   - HUD 命中反馈不过量，不影响其他特效层

## 11. 非目标

以下内容不在本次范围内：

1. 不引入 Zustand 或全局状态库迁移。
2. 不重做现有种子选择器和 HUD 的整体架构。
3. 不新增复杂的 Canvas/WebGL 粒子系统。
4. 不改造抽奖系统、背包系统或主题皮肤经济逻辑。
5. 不在本次中引入“一键浇水”“一键施肥”等额外批量操作。

## 12. 实施顺序建议

建议按以下顺序落地：

1. 在 `useGameActions.ts` 补齐批量规划与提交纯函数。
2. 在对应测试中先写失败断言。
3. 在 `App.tsx` 增加 bulk controller、本地状态和一键按钮入口。
4. 在 `Plot.tsx` 增加批量表现态 props 与基础命中反馈。
5. 最后补 `PlantFlight` / `HarvestFlight` 的第一版近似抛物线动画。
