# 土地核心重塑设计

- 日期：2026-04-22
- 范围：`src/components/Plot.tsx`、`src/index.css`、`src/text-sanity.test.ts`
- 目标：将当前“按钮感”明显的地块，重构为更像真实翻土的 2D 平视泥土地块，在不新增图片资源、不改动主交互逻辑的前提下，补齐材质、厚度和收获反馈。

## 1. 背景与问题

当前地块虽然已经具备基础坑位、成长条、倒计时、收获提示和部分动画，但主视觉仍由单块圆角矩形驱动：

1. `.plot-base` 的轮廓过于规整，整体更像一个可点击卡片，而不是翻起的泥土。
2. `soil-texture` 只提供了轻量平铺纹理，没有建立真实的土层厚度、边缘破碎感和与背景的贴合感。
3. 空地状态的 `dirt-pit` 有内凹意图，但坑口与地块主体之间缺少更完整的土层关系。
4. `isWatered` 当前只是整块变暗加一层泛蓝光，湿润感偏 UI 效果，不像真实土壤。
5. 收获时已有 `scale` 动画，但反馈仍偏“控件缩放”，缺少泥土飞溅和松软回弹带来的解压感。

本次改动不触及播种/收获流程、成长时间计算、拖拽收获逻辑和神泉主题已有的神性作物特效入口，只做地块本身的视觉重塑。

## 2. 设计目标

本次设计采用“程序化泥土重构”路线，遵循以下原则：

1. 不新增本地图片或外部素材，所有泥土纹理、碎边、厚度、湿润高光和粒子都使用现有 CSS、渐变和 `motion` 生成。
2. 保留当前地块组件的功能结构，让播种、成长、成熟、拖拽收获行为完全不回归。
3. 先统一重构所有地块的基础泥土层，再让 `sacred_spring` 皮肤继续在此基础上叠加已有主题特效。
4. 视觉上优先解决“像按钮”的问题，而不是追求过量发光或复杂渲染。
5. 动效以“松软、Q 弹、解压”为目标，避免把土地做成高频闪烁的 UI 元件。

## 3. 方案概述

### 3.1 分层结构重组

`Plot.tsx` 将从当前“单容器 + 纹理覆盖”的结构，调整为四层组织：

1. `shadow`：最底部厚度层，向下偏移 4-6px，负责承载地块被翻起后的侧边阴影和落地感。
2. `soil`：主体泥土层，负责土色、颗粒、内缘压暗、湿润高光和地表深浅过渡。
3. `ambience`：轻量装饰层，用程序化碎土、裂口、草尖或小凸起打破边缘过整的问题。
4. `content`：作物、空坑、成长条、倒计时、成熟角标等功能内容，保持语义独立，不与泥土材质耦合。

这样调整后，地块的“形体”和“功能信息”会分离，后续即便继续补特效，也不会再把泥土本身写成一整块背景色。

### 3.2 状态到视觉的映射

不同地块状态对应不同的泥土表现：

1. 空地：
   - 坑位最明显。
   - 坑口周围有更强的内凹阴影。
   - 整体偏干，突出“等待播种”的裸土感。
2. 已播种未成熟：
   - 坑位弱化为种植痕迹，不再像空洞黑圈。
   - 土色回到正常焦褐色。
   - 保留细颗粒和松散感，衬托成长中的作物。
3. 湿润状态（`isWatered`）：
   - 主体颜色变深，顶部局部有柔和高光。
   - 不使用强蓝色覆盖层，而是通过暗湿土色和窄范围反光模拟水分。
4. 可收获状态：
   - 不再依赖整块土地的强发光 pulse。
   - 通过轻微提亮边缘、稍增强厚度层和保留成熟角标来表达“可收获”。

### 3.3 2.5D 厚度与贴地感

为了在平视 2D 中做出“地块真的坐在地面上”的感觉，采用以下伪深度手段：

1. 主体层下方增加深色厚度条，表现翻起泥块的侧壁。
2. 地块与外部背景交界处增加一圈极轻的环境遮蔽（AO），让泥土不再像漂浮控件。
3. 主体泥土层顶部更亮、底部更深，并在内缘增加压暗，制造土层厚度。
4. 空坑本身改为更完整的坍塌式渐变，而不是单纯黑色圆洞。

### 3.4 有机质感与边缘破碎

不规则感主要通过 CSS 叠层实现：

1. 主体泥土层加入多段径向渐变和低透明度颗粒斑点，形成矿物噪点。
2. `ambience` 层在边缘布置数个小块状/草尖状元素，模拟碎土突起。
3. 边缘不做锯齿化硬裁切，仍保留整体可控的圆角，但局部打破“完美圆角矩形”观感。
4. 现有 `soil-texture` 可以保留为兼容纹理层，但不再作为视觉主力。

### 3.5 交互动画与粒子

交互反馈限定为“按压 + 收获”两条主路径：

1. 按压反馈：
   - 保留 `whileTap`。
   - 调整为更像松土下陷的反馈，例如 `scale: 0.96` 配合轻微下沉。
2. 收获回弹：
   - 升级为 `scale: [1, 0.9, 1.1, 1]`。
   - 时长约 0.42 秒，突出 Q 弹感。
3. 泥土粒子：
   - 仅在“收获成功”时触发。
   - 由组件内部生成 6-8 个短生命周期粒子，颜色取深褐到浅褐之间。
   - 粒子从地块中心向四周和上方扩散，约 0.45 秒淡出。
4. 空坑呼吸感：
   - 保持极弱的亮暗浮动，只作为静态画面活性，不影响播种判断。

### 3.6 与神圣神泉主题的兼容

这次只重构“基础泥土层”，不把 `sacred_spring` 单独做成另一套土地组件：

1. `sacred_spring` 继续复用新的基础泥土结构。
2. 现有 divine 作物神性特效入口保留，不拆、不改触发逻辑。
3. 如果地块上已经有神泉背景模糊叠层，则继续作为额外装饰存在，而不是替代泥土主体。

## 4. 组件与数据流影响

### 4.1 `src/components/Plot.tsx`

需要调整的内容：

1. 用更明确的层级容器替换当前“单个 `.plot-base` + 一个纹理覆盖层”的结构。
2. 增加用于描述泥土状态的派生变量，例如是否湿润、是否为空地、是否成熟。
3. 保留当前 `timeLeft`、`growthProgress`、`handleInteract`、`handlePointerEnter` 等逻辑，不改流程。
4. 将当前 `isSquishing` 的回弹动画升级为新的收获序列，并增加粒子触发时机。
5. 保留现有作物渲染和成长条逻辑，让这次改动聚焦土地本体。

建议新增的结构标记应具备明确语义，例如：

1. `soil-shadow`
2. `soil-surface`
3. `soil-ambience`
4. `soil-particles`

这些标记也会被回归测试使用，防止后续重构时把土地重新写回“单层背景块”。

### 4.2 `src/index.css`

需要调整的内容：

1. 重写 `plot-base` 的视觉职责，让它退化为整体容器而不是主视觉来源。
2. 新增泥土分层类，包括厚度、主体、湿润态、空坑态、成熟态和装饰层。
3. 保留与现有类兼容的基础过渡配置，避免影响其他调用点。
4. 如果保留 `soil-texture`，则将其降级为辅助纹理，而不是唯一材质来源。

### 4.3 `src/text-sanity.test.ts`

需要新增文本级回归断言，用于锁住这次重构的关键结构与动画标记：

1. 地块包含新的分层标识，例如 `soil-shadow`、`soil-surface`、`soil-ambience`、`soil-particles`。
2. 收获动画包含 `scale: [1, 0.9, 1.1, 1]`。
3. 湿润态存在新的泥土状态控制，而不是只有旧的整块变色逻辑。
4. 粒子生成与渲染逻辑存在明确标记。

测试仍然是字符串级防回归，不负责校验最终视觉效果是否“好看”，但足够防止结构被误删。

## 5. 异常与兼容性考虑

1. 当前工程已有部分中文文本编码历史问题，这次改动尽量只触碰土地相关代码，避免误伤其他已有字符串。
2. 粒子状态必须是短生命周期并及时清理，避免连续收获时累积无用节点。
3. 收获粒子只能在真正收获成功后触发，不能在空地点击或成长中点击时误触发。
4. 拖拽收获时 `handlePointerEnter` 仍可能连续触发，因此粒子创建应依赖成功收获后的状态切换，而不是单纯依赖悬停事件。
5. 如果 `plot-base` 在其他地方被隐式依赖，需保留该类名作为兼容入口，避免牵连非目标样式。

## 6. 测试与验证策略

本次改动以组件结构和样式重构为主，但仍需遵循最小验证闭环：

1. 先修改 `src/text-sanity.test.ts`，为新的土地分层和收获动画写失败断言。
2. 运行 `npx tsx --test src/text-sanity.test.ts`，确认失败原因正确。
3. 再实现 `Plot.tsx` 与 `index.css` 中的最小代码，让测试转绿。
4. 运行 `npm test`，确认现有文本级测试未回归。
5. 运行 `npm run lint`，确认 TypeScript 未被新状态字段或类名重构破坏。
6. 最后做一次手工 UI 检查，确认：
   - 空地看起来像真实种植坑，而不是黑色按钮中心。
   - 土地有厚度和贴地感。
   - 湿润态更像湿土而不是蓝色遮罩。
   - 收获时的 Q 弹和飞土粒子自然且不过量。

## 7. 非目标

以下内容明确不在本次范围内：

1. 不新增任何图片、贴图、SVG 资源文件。
2. 不修改 `App.tsx` 的拖拽收获主流程。
3. 不修改作物成长时间、播种/收获算法和经济数值。
4. 不改造作物 icon、抽奖系统、背包系统和其他 HUD 组件。
5. 不将 `sacred_spring` 做成一套完全独立的地块实现。

## 8. 实施顺序

建议实现顺序如下：

1. 先在 `src/text-sanity.test.ts` 写新的土地重构失败断言。
2. 再改 `src/components/Plot.tsx` 的层级结构和收获粒子状态。
3. 然后在 `src/index.css` 落地新的泥土层、湿润态、厚度和装饰样式。
4. 最后运行测试、类型检查和手工预览。
