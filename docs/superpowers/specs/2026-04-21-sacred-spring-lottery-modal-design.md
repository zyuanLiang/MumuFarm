# 神泉抽奖弹窗视觉优化设计

- 日期：2026-04-21
- 范围：`src/components/LotteryModal.tsx`、`src/constants.ts`
- 目标：在不重做抽奖弹窗结构和交互逻辑的前提下，提升神泉主题弹窗的层级感、可读性和禁用态反馈质量。

## 1. 背景与问题

当前 `LotteryModal` 已具备神泉主题背景、奖励展示、抽奖按钮和底部奖池列表，但在 `sacred_spring` 皮肤下仍存在以下问题：

1. 弹窗主体虽然与背景融合自然，但边缘感偏弱，层级不够清晰。
2. 弹窗缺少明确标题区，首次进入时功能引导不足。
3. “金币储备不足”禁用态偏硬，像一层直接盖上去的遮罩，压迫感有了，但质感不足。
4. 底部奖池列表卡片悬浮感偏强，未形成明显的“槽位”节奏。
5. 神泉主题的弹窗强调色和遮罩色没有通过皮肤配置统一管理，组件内存在写死样式。

本次优化不改变抽奖逻辑、奖励逻辑、状态流和现有布局骨架，只做最小必要的视觉增强。

## 2. 设计目标

本次改动采用“保守增强”方向，遵循以下原则：

1. 保留当前弹窗结构，不新增复杂区域，不改变主要交互路径。
2. 强化弹窗边界和玻璃拟态质感，但避免喧宾夺主，不能抢过奖励卡片本身。
3. 新增标题和辅助说明，提升弹窗的功能识别度。
4. 让禁用态看起来更“不可点击”，而不是仅仅显示红字提示。
5. 让底部奖池卡片形成统一的槽位感，并提高文字在复杂背景上的可读性。
6. 将神泉皮肤的部分弹窗样式参数下沉到 `SKINS` 配置，避免组件内持续堆积皮肤特判。

## 3. 方案概述

### 3.1 弹窗容器层级

优化弹窗主容器的视觉层级，但不改变尺寸、位置和整体布局：

1. 在现有深色容器上增加极细边框，例如 `border-white/10` 附近的强度。
2. 增加轻微的青蓝色外发光，用于将弹窗从神泉背景中“提”出来。
3. 将主体背景从纯色调整为轻微的纵向渐变，上深下稍透，模拟顶部受光。
4. 保持磨砂玻璃方向，但将模糊强度从当前强度上调一档，以降低复杂背景带来的噪音。

预期结果：

1. 弹窗边缘更清晰。
2. 整体仍然贴合神泉主题，不会变成高饱和赛博风。
3. 奖励卡片仍然是视觉中心。

### 3.2 标题区

在弹窗顶部增加一个轻量头部，不引入新的操作逻辑：

1. 主标题固定为 `神泉商店`。
2. 副文案使用一行弱提示，例如“献祭金币，换取神泉赐福”。
3. 标题区布局采用轻量左对齐，与右上角关闭按钮共存，不重排整个弹窗结构。

设计原因：

1. `神泉商店` 比 `限时兑换` 更贴近当前弹窗的功能入口定位。
2. 头部是最小成本但收益很高的引导增强点。

### 3.3 抽奖按钮与禁用态

主按钮继续使用当前的椭圆按钮结构，不换组件，不改文案体系：

1. 可点击状态：
   - 增加 `hover` 亮度提升或阴影增强。
   - 保留 `active` 缩放反馈。
2. 不可点击状态：
   - 不再使用强覆盖感的硬遮罩作为唯一表现。
   - 按钮底色整体压暗，整体透明度下调。
   - 红色提示文案保留，但增加轻微内发光或弱阴影，使其更像“能量不足”的状态。
   - 保持 `disabled` 语义和现有逻辑判断不变。

预期结果：

1. 用户可以更直观地区分“可抽取”和“不可抽取”。
2. 禁用态会更精致，避免像报错蒙层。

### 3.4 底部奖池列表槽位感

底部列表保持横向布局，不更改数据结构和渲染顺序，只改视觉包装：

1. 给每个奖池卡片增加更稳定的槽位底色，未选中态使用深色半透明底。
2. 给卡片容器补轻微内阴影和边框，让它看起来是嵌入底座中的，而不是漂浮在空中。
3. 维持当前高亮项的光效，但普通项的存在感通过“底座”来建立，而不是仅靠透明背景。
4. 奖品名称增加非常轻的 `text-shadow`，提升在复杂背景和高对比图片上的可读性。

### 3.5 神泉皮肤 UI 配置下沉

在 `SKINS.sacred_spring` 上增加面向弹窗的 UI 配置字段，最小可用集合如下：

```ts
sacred_spring: {
  bgImage: '/assets/backgrounds/bg_sacred_spring.png',
  secondary: '#1A1D2D',
  accentColor: '#4FD1C5',
  modalOverlay: 'bg-slate-950/80',
}
```

说明：

1. `accentColor` 用于抽奖按钮、边缘光效、标题区弱强调色等。
2. `modalOverlay` 用于外层遮罩风格统一。
3. 本次只接入 `LotteryModal` 使用，不顺带重构其他组件，避免扩大影响范围。

## 4. 组件与数据流影响

### 4.1 `LotteryModal.tsx`

需要调整的内容：

1. 读取神泉皮肤新增的 UI 配置。
2. 调整根容器和底部操作区的 className / inline style，增强层级和渐变。
3. 在内容区顶部新增标题与弱提示文案。
4. 修改抽奖按钮的可点击与禁用态样式表现。
5. 调整底部奖池列表 item 容器样式，并补文字阴影。

不变的内容：

1. `handleDraw` 的行为与时序。
2. `gold < LOTTERY_COST` 的禁用判定。
3. 奖励展示逻辑与稀有度视觉逻辑。
4. `PRIZE_POOL` 数据结构和展示顺序。

### 4.2 `constants.ts`

需要调整的内容：

1. 为 `sacred_spring` 增加 `accentColor`、`modalOverlay` 等 UI 配置字段。

注意：

1. 如果 `SKINS` 当前未声明显式类型，可先做兼容性最小改动。
2. 避免为了这次样式增强而把全量皮肤配置体系重写一遍。

## 5. 异常与兼容性考虑

1. 若某个皮肤没有 `accentColor` 或 `modalOverlay`，`LotteryModal` 必须回退到现有默认值，不能因为字段缺失导致样式异常。
2. 新增标题区后，关闭按钮与标题不能在小屏重叠，需要保持现有移动端宽度下可用。
3. 按钮禁用态样式增强不能影响 `disabled` 属性本身的语义，必须继续阻止点击。
4. 底部列表新增槽位背景后，不能影响横向滚动和现有遮罩渐隐效果。
5. 文本阴影必须非常轻，避免中文字体在小字号下糊成一团。

## 6. 测试与验证策略

本次改动主要是 UI 样式调整，但仍需要进行最低限度的自动验证：

1. 更新或补充 `src/text-sanity.test.ts`，校验以下关键内容仍存在：
   - `神泉商店`
   - 新增的神泉皮肤 UI 配置字段
   - `LotteryModal` 中用于层级增强和禁用态的关键样式标记
2. 运行 `npm test`，确保文本与结构检查不回归。
3. 运行 `npm run lint`，确保 TypeScript 类型未被新配置破坏。

如果本地环境允许，还应补充一次手工预览确认：

1. `sacred_spring` 皮肤下弹窗边界清晰但不过曝。
2. 余额不足时按钮明显不可点击。
3. 底部普通卡片有槽位感，高亮项依然最突出。

## 7. 非目标

以下内容明确不在本次范围内：

1. 重做 `RewardDisplay` 奖励卡片结构。
2. 修改抽奖逻辑、动画时长或概率逻辑。
3. 把同一套视觉体系同步到 `SeedSelector`、`HUD` 等其他浮层组件。
4. 引入新的状态管理字段或重构全局主题系统。

## 8. 实施顺序

建议的实现顺序如下：

1. 先扩展 `SKINS.sacred_spring` 配置，提供弹窗所需的主题参数。
2. 再改 `LotteryModal` 主容器、标题区和底部容器层级。
3. 然后调整主按钮的可点击态和禁用态。
4. 最后处理底部列表卡片槽位感与文字阴影。
5. 补充文本/结构测试并执行验证命令。
